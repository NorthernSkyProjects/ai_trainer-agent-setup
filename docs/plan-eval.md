# Plan Eval — рубрика оценки ИИ-плана тренировок

Назначение: единая планка качества для результата `ai_generator` (и ручного конструктора),
которую можно проверять детерминированно или через `quality-check`. Связана с
наблюдаемостью (`ai_metrics.py`) и golden-set в `tests/ai_fixtures.py`.

Доктрина: **сначала evals, потом loop.** Изменения в промптах/нормализации/каталоге
оцениваем по этой рубрике, а не «на глаз».

## Как проверять

1. **Автотесты (детерминированно):** `tests/test_ai_pipeline.py`, `tests/test_ai_generator.py`,
   `tests/test_health_focus.py` — структура, каталог, фильтрация. Прогон: `.venv/bin/python -m pytest -q`.
2. **Метрики (прод/дев):** `/ai_metrics` — `generations_total`, `cache_hits/misses`,
   `fallbacks_total`, `rejected_exercises_total`, `avg_latency_ms`.
3. **Ручная оценка (субъективное):** только через `quality-check` с этой рубрикой.

## Критерии (0/0.5/1, взвешенно)

| # | Критерий | Вес | Как проверять | Провал |
|---|--:|---|---|---|
| C1 | **Валидность структуры** | 0.25 | `week{N}` → `day{M}` → список `{exercise, sets, reps, weight, comment}`; нет пустых дней/неделин | отсутствует ключ, пустой день, не-список |
| C2 | **Соблюдение каталога** | 0.20 | все упражнения сопоставлены (`match_entry`), нет выдуманных | «Квантовое сальто Зета» прошло в план |
| C3 | **Безопасность (ограничения/возраст/здоровье)** | 0.25 | исключены противопоказанные (`ensure_focus_exercises`/фильтр каталога) | запрещённое упражнение в плане |
| C4 | **Учёт инвентаря** | 0.10 | упражнения соответствуют `equipment` профиля | штанга у пользователя без зала |
| C5 | **Соответствие цели/опыта/частоты** | 0.10 | объём/интенсивность не противоречат `goal`, `experience`, `frequency` | фулбади 2×/нед на «набор массы, advanced» |
| C6 | **Описания гарантированы** | 0.05 | у каждого упражнения есть название/описание | пустой `comment`, нет RU-названия |
| C7 | **Разумность подходов/повторов/веса** | 0.05 | sets 1–10, reps 1–50, weight ≥ 0 или null | отрицательный вес, 999 подходов |

Формула: `score = Σ (вес × оценка)`. Порог: **≥ 0.9** — план годен; `0.7–0.9` — правка
нормализации/промпта; `< 0.7` — стоп, разбираться до мержа.

## Свидетельства (обязательны)

- C1/C2/C3 — вывод конкретных тестов (не «прошло»), список отклонённых упражнений из
  `rejected_exercises_total` и лога `ai_generation`.
- C6 — пример 2–3 описаний из результата.
- C7 — пример строки `{exercise, sets, reps, weight}`.

## Дрейф и «тихая недоделка»

- План должен отвечать на профиль пользователя, а не быть «типовым».
- `[GAP]` — если не проверено (например, генерация шла на фолбэке модели).
- `fallbacks_total > 0` — отметить: качество могло просесть, проверить вручную.

## История

Рубрика заведена по итогам разбора презентации «Управление Coding агентом» (loop engineering:
«цикл настолько хорош, насколько хорош его критерий завершения»).
