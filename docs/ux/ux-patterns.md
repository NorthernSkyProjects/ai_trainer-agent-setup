# UX-паттерны Kachlog: экраны, переходы, состояния

**Дата:** 2026-11-14
**База:** текущий интерфейс продукта и дизайн-система Kachlog.
**Принцип:** не изобретаем новый визуальный язык; фиксируем паттерны текущего shadcn-дизайна
и закрываем пробелы в состояниях и переходах.

## 2. Сценарии и переходы

### A. Первый пользователь

```
/register → /consent → /onboarding (1…10) → /onboarding/mode
  ├─ ИИ → /onboarding/generating → /plan
  └─ конструктор → /plan-builder → /plan
→ /workout/today → /workout/result → /plan
```

Правила:
- на шагах онбординга «Назад» не теряет введённое;
- генерация не блокирует вкладку: можно уйти, статус доступен при возврате;
- после генерации сразу виден план и главный CTA «Начать тренировку»;
- первый запуск не показывает пустой дашборд.

### B. Возвращающийся пользователь

```
/login → /plan
  ├─ «Начать тренировку» → /workout/today → /workout/result
  ├─ «Обновить с ИИ» → sheet/dialog → pending → /plan
  └─ «История» → /history → /history/edit
```

Правила:
- на `/plan` сразу видно «сегодня» и прогресс цикла;
- AI-диалог не уводит со страницы; pending и ошибка остаются в контексте;
- после сохранения тренировки — результат, затем возврат к плану.

### C. Ручной план

```
/plan → /plan-builder → день → упражнение → черновик → активация → /plan
```

Правила:
- черновик сохраняется автоматически;
- предупреждения о несовместимости с оборудованием/ограничениями видны до активации;
- активация заменяет текущий план только после подтверждения.

### D. Прогресс и шеринг

```
/plan → /plan/summary → /progress → /progress/exercise
/workout/result → «Поделиться» → Telegram / публичная ссылка
```

Правила:
- на итогах цикла один главный CTA «Составить новый план»;
- графики не обещают точность выше данных;
- публичная ссылка не раскрывает email и health-данные.

## 3. Переходы и навигация

| Контекст | Desktop | Mobile |
|---|---|---|
| Основная навигация | sidebar (inset, collapsible) | bottom tab bar (4 таба + «Ещё») |
| Вложенные разделы | подпункты в sidebar | sheet из «Ещё» |
| Заголовок | breadcrumbs | заголовок страницы |
| Диалоги | `dialog` по центру | `sheet` снизу |
| Долгие действия | inline pending в диалоге | тот же sheet + прогресс |
| Назад | breadcrumb/браузер | системная кнопка/шапка |
| Офлайн | бейдж в шапке | бейдж в шапке |

Правила:
- не смешивать dialog и sheet на одном брейкпоинте;
- destructive-действия — отдельный шаг подтверждения;
- закрытие sheet во время pending блокируется, показывается «Отменить»;
- после действия — toast, но не единственный источник результата.

## 4. Пять состояний

Для каждого ключевого экрана обязательны:

| Состояние | Что показываем | Пример |
|---|---|---|
| **Empty** | одна причина + один CTA | «Плана пока нет» → «Составить план» |
| **Loading** | skeleton или текст + прогресс | «Загружаем план…»; генерация — этапы |
| **Partial** | что уже есть + чего ждём | разбор `stale` + базовый разбор |
| **Error** | причина простым языком + retry | «ИИ недоступен» → «Повторить» |
| **Success** | результат + следующий шаг | тренировка сохранена → «К плану» |

Дополнительно:
- **Offline** — бейдж + работа с кэшем; форма не теряет ввод;
- **Slow** — после порога меняем текст, не крутим спиннер бесконечно;
- **Skeleton** — только для предсказуемой структуры, не для диалогов.

## 5. AI UX

### Генерация плана

1. **До запуска:** показываем, что учтём (профиль, оборудование, ограничения) и сколько ждём.
2. **Во время:** список этапов (анализ профиля → подбор упражнений → проверка ограничений →
   сборка недель), прогресс, таймер; после 60–90 с — «сервис загружен».
3. **Ошибка:** причина + «Повторить»; план не создаётся молча.
4. **Успех:** план появляется сразу; первый экран — «Сегодня».

### Пересчёт плана

- диалог/sheet с быстрыми пожеланиями и свободным комментарием;
- «Учесть историю тренировок» включено по умолчанию;
- «Память тренера» раскрывается, видно, что учтено;
- pending: анимация + «ИИ перестраивает план…», кнопка «Отменить»;
- ошибка: текст + возможность исправить комментарий, не закрывая всё;
- успех: toast + обновлённый план, без перезагрузки страницы.

### Разбор тренировки

- `pending`: skeleton + «Обычно до минуты»;
- `ready`: краткое резюме + по упражнениям + рекомендация;
- `stale`: «разбор задерживается» + базовый разбор + ссылка в историю;
- `failed`: причина + базовый разбор + «Повторить» (если доступно);
- `skipped`: «сохранено без ИИ» + базовый разбор.

### Принципы

- ИИ никогда не скрывает сохранённые данные.
- Любое автоматическое изменение можно отменить или подтвердить.
- Объяснение — одна строка, не абзац.
- Стоимость/квота видимы до действия, если она ограничена.

## 6. Доступность и эргономика

- Тач-цели ≥44×44 px на mobile; desktop — dense, но не меньше 28 px.
- Фокус видим: `ring-2 ring-ring/30`, не убирать outline без замены.
- Контраст текста ≥4.5:1; крупный текст ≥3:1.
- Цвет — не единственный носитель смысла: иконка/текст/форма.
- Все интерактивные элементы доступны с клавиатуры.
- `aria-current`, `aria-expanded`, `aria-live` для статусов.
- `prefers-reduced-motion` отключает fade/slide/ping.
- Ошибки — рядом с полем, простым языком, с действием.

## 8. Что улучшаем в концепте (без изменения кода)

1. Явно описать **accent-токен** teal для прогресса/PR, а не только `chart-*`.
2. Добавить **motion-токены** (160–220 ms, ease-out) и reduced-motion.
3. Зафиксировать **5 состояний** как обязательный чек-лист для новых экранов.
4. Добавить **AI UX** раздел с шагами, optimistic, retry и «Отменить».
5. Зафиксировать **don'ts**: градиенты, эмодзи-карточки, чужие шрифты, больше одного акцента.
6. Добавить **контентные правила**: цифры — mono/tabular, вес — кг, даты — `дд.мм`.
