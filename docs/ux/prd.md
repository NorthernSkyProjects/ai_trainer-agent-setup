# Kachlog — PRD (сжатая версия для модуля 3)

**Дата:** 2026-11-14
**Статус:** контекст для дизайн-концепта.
**Источники:** описание продукта, PRD, продуктовые метрики, текущие экраны.

## 1. Что это за продукт

Kachlog — русскоязычный веб-продукт (PWA) для ведения силовых тренировок и получения
персонального плана. Пользователь заполняет анкету (цель, опыт, оборудование, здоровье,
ограничения), получает план от ИИ или собирает его вручную, тренируется по этому плану,
логирует подходы, получает разбор тренировки и видит прогресс.

Ключевая ценность: **безопасный персональный план + надёжный журнал тренировок**.
План не должен содержать упражнений, запрещённых ограничениями, возрастом или здоровьем.

## 2. Пользователи и jobs-to-be-done

| Сегмент | Что хочет | Что мешает |
|---|---|---|
| Новичок в зале | «Скажи, что делать сегодня, и не дай навредить» | Страх ошибиться, непонятные упражнения, много вариантов |
| Возвращающийся после паузы | Быстро восстановить режим без перегруза | Нет памяти о прошлых весах, страшно начать слишком тяжело |
| Домашний/уличный тренирующийся | План под гантели/свой вес | Приложения предполагают зал |
| Продолжающий | Не тратить время на планирование, видеть прогресс | Ручные таблицы, разрозненные заметки |
| Человек с ограничениями | Безопасные замены и понятные объяснения | ИИ выдаёт запрещённое, нет прозрачности |

## 3. Сценарии

1. **Первый запуск:** регистрация → согласие → онбординг (10 шагов) → выбор способа (ИИ/конструктор)
   → генерация → план → первая тренировка → результат.
2. **Возвращение:** вход → «Мой план» → «Начать тренировку» → лог подхода → завершение → разбор.
3. **Ручной план:** конструктор → дни/упражнения → черновик → активация → тренировка.
4. **Прогресс:** история → графики/PR → итоги цикла → новый план.
5. **Шаринг:** результат → текстовый отчёт → публичная ссылка/Telegram.

## 4. Scope модуля 3

Входит:
- ресерч конкурентов и UX-паттернов;
- челлендж PRD и фиксация продуктовых допущений;
- DESIGN.md по текущей реализации `/next/plan`;
- UX-карта экранов, переходов и состояний;
- demo-экран, собранный по DESIGN.md, и скриншоты desktop/mobile;
- GSD-фазы `discuss` и `plan`.

Не входит:
- изменение прод-кода, миграции, деплой;
- новые продуктовые фичи в Flask/Next;
- копирование брендов конкурентов, их логотипов и контента;
- публикация PDF урока.

## 5. Метрики

Уже есть в `product_metrics.py`; для дизайна важны:

| Метрика | Определение | Зачем дизайну |
|---|---|---|
| Activation | регистрация → онбординг → план → первая тренировка | где теряются новички |
| Adherence | завершённые тренировки / запланированные за цикл | работает ли план |
| W4 retention | доля вернувшихся на 4-й неделе | удержание |
| AI success rate | `analysis_status=ready` / все разборы | доверие к ИИ |
| Share rate | доля тренировок с отчётом/ссылкой | виральность |
| Time-to-first-set | от входа до первого сохранённого подхода | скорость лога |

## 6. Ограничения

- Русскоязычный интерфейс, код и коммиты — на английском.
- PWA, мобильный веб, офлайн-доступ к плану/тренировке/истории.
- Безопасность: CSRF, rate limits, медицинский дисклеймер, запрещённые упражнения.
- ИИ не является медицинским советом; ошибки ИИ должны быть видимы и восстановимы.
- Дизайн — shadcn/ui (`base-nova`), Tailwind v4, Lucide; без CDN и сторонних UI-китов.

## 7. Риски

| Риск | Влияние | Смягчение |
|---|---|---|
| ИИ выдаёт опасное упражнение | здоровье, доверие | детерминированная фильтрация + понятное объяснение |
| Слишком много шагов онбординга | отвал до плана | прогресс, «назад», сохранение черновика |
| Лог тренировки медленный | не заполняют | крупные контролы, «в прошлый раз», автотаймер |
| Непонятно, почему план такой | не доверяют | «Память тренера», объяснение изменений |
| Ошибка ИИ выглядит как баг | уходят | 5 состояний, причина, retry, базовый разбор |
