# design-check — ревью UI по DESIGN.md

## Когда применять
- Перед завершением любой UI-правки в `/next` (`web/**`) или demo-экране (`design/**`).
- По запросу «проверь дизайн», «design review», «/design-check».
- Не применять к чистой логике, API, миграциям и текстам без UI.

## Что прочитать
1. `DESIGN.md` — токены, типографика, сетка, компоненты, 5 состояний, AI UX, motion, don'ts.
2. `docs/ux/ux-patterns.md` — экраны, переходы, состояния, AI UX.
3. `screenshots/module3/` — референс и demo-скриншоты (если есть).

## Проверка

| Критерий | Что смотреть |
|---|---|
| Scope | `/next` UI следует DESIGN.md; legacy Flask не смешивать |
| Токены | только семантические токены, без hex и новых цветов |
| Типографика | Inter + Geist Mono, mono/tabular для чисел |
| Сетка | 4/8 px, радиус 10 px, ring 1px, без тяжёлых теней |
| CTA | один primary на смысловой блок, максимум два на экран |
| Состояния | empty / loading / partial / error / success |
| AI UX | шаги, pending, отмена, retry, объяснение |
| Доступность | 44px mobile, контраст 4.5:1, фокус, reduced motion |
| Don'ts | без градиентов, эмодзи, второго акцента, чужих шрифтов |

## Формат ответа
1. **Вердикт:** pass / fail.
2. Таблица: критерий → pass/fail → доказательство (файл:строка или скриншот).
3. Блокирующие замечания: что исправить.
4. Некритичные улучшения.
5. Если fail — не завершай задачу, пока блокеры не исправлены.

## Границы
- Не переписывай дизайн «на вкус»: истина — DESIGN.md.
- Не добавляй новые токены/шрифты без обновления DESIGN.md.
- Не трогай legacy Flask-стили, если задача явно не про миграцию.
