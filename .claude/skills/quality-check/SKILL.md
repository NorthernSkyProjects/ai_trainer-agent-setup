# quality-check — проверка ИИ-артефакта перед использованием

Автор исходной методологии: Dmitrii Yuzhanin, https://github.com/MainFrame100/quality-check-skill
Лицензия: CC BY 4.0 (сохранять атрибуцию при распространении/адаптации).

Цель — не доказать, что артефакт идеален, а вскрыть необоснованные утверждения, выдуманные
числа, слабые выводы, дрейф от исходной задачи и неясную готовность. Применяй к артефактам,
которые создал ИИ (наш случай: результат `ai_generator`/`report.py`, ответы агента, сводки).

## Когда НЕ использовать
- Тривиальные правки и обычная переписка без артефакта.
- Код-ревью (это отдельная задача, не «артефакт на доверие»).
- Когда нет исходного запроса/источников для сверки — тогда сначала запроси их.

## 1. Anti-Victory
Назвать, что НЕ сделано, НЕ проверено, НЕ известно. В отчёте обязательна хотя бы одна
ограниченность либо явное объяснение, почему существенных нет. Метки:
- `[GAP]` — не хватает данных;
- `[GAP: чей ход?]` — неясен ответственный/следующий шаг;
- `[ДОБАВЛЕНО]` — интерпретация агента, которой нет в источнике.

## 2. Честный вердикт
Один из: `Готово как есть` · `Нужна правка` (перечислить конкретные) · `STOP` · `BLOCKED` (нет источников).

## 3. Дрейф от задачи
Сверь результат с исходным запросом: ответил ли на то, что просили; не добавил ли лишних целей;
не сместился ли от фактов к советам/мнениям без запроса; сохранён ли адресат.
Формат: `Дрейф: из [изначальный объём] в [фактический]`.

## 4. Протокол возражений (4 проверки)
1. `Инверсия` — назови сценарий, где результат ломается.
2. `Что не искали` — информация, которая могла бы изменить вывод.
3. `Стальная альтернатива` — какие данные подтвердили бы противоположный вывод.
4. `Аудит допущений` — какие факты приняты без проверки.

## 5. Верификация источников
Инвентаризуй проверяемые утверждения: `ЧИСЛО`, `ПРОЦЕНТ`, `МНОЖИТЕЛЬ` (в т.ч. «несколько раз»,
«в разы» — риторические, их пропускают чаще всего), `СРОК` (точные даты/длительности),
`ЦИТАТА`, `СРАВНЕНИЕ`, `ИНТЕНСИФИКАТОР` («всегда», «никогда», «лучший»), `ВЛАДЕЛЕЦ`.
- Проверяй 100%: числа, проценты, точные множители, точные сроки, атрибуцию цитат.
- 30-секундное правило: не можешь назвать источник за 30 секунд → помечай `[ДОБАВЛЕНО]`/`[GAP]`.
- Вердикт по каждому: `[ПОДТВЕРЖДЕНО: источник]` · `[ПРОТИВОРЕЧИТ: источник]` · `[НЕ НАЙДЕНО]` ·
  `[ИСТОЧНИК НЕДОСТУПЕН]` · `[ДОБАВЛЕНО]`.
- Число без источника — это галлюцинация, а не оговорка: удали точность или помечай.
- В финале — только расхождения (коротко), не список подтверждённого.

## 6. Скоринг D/L/C/P
| Критерий | Вес | Смысл |
|---|--:|---|
| D — Данные | 0.4 | факты подтверждены источниками |
| L — Логика | 0.3 | вывод следует из данных |
| C — Согласованность | 0.2 | нет внутренних противоречий |
| P — Пропорциональность | 0.1 | вывод не сильнее доказательств |
Каждый критерий: `0` / `0.5` / `1`, затем взвешенная сумма. Оценка без доказательства недействительна.
`0.8+` — можно продолжать; `0.5–0.8` — черновик; `<0.5` — не хватает данных; `<0.2` — не строить финальные артефакты.
Штрафы: код не тестировался, данные не проверены, ключевой источник недоступен.

## 7. Когнитивные искажения
Проверь: подтверждение (только за), выжившего (только успешные кейсы), ложная модель,
ложная дихотомия, категориальная ошибка уровней (метрика, склеенная из разных ролей).

## 8. Тесты
Для кода/данных/операционных утверждений — фактическое свидетельство: stdout/stderr, строки
данных, «до/после», реальный вывод. Ничего не запускалось → пиши `Не тестировано`.

## 9. Самодиагностика галлюцинаций
Остались неподкреплённые числа/даты; тон увереннее, чем доказательства; факты слишком удобно
подтверждают вывод; категоричность без источника; цитаты не проверены. Два+ признака → нужна правка.
Заодно чисти следы редактуры («ранее X, теперь Y», «пересобрано») — финальный артефакт читается как написанный с нуля.

## Шаблон self-check для субагента
```
Перед возвратом проверь:
1. Что не покрыто? Что не удалось найти?
2. Для каждой цитаты — конкретный источник (файл+строка). Нельзя → [GAP: атрибуция не проверена].
3. Для каждого числа — как получено. Оценка → [GAP: точное число не посчитано], не выдавай за факт.
4. Можно ли использовать как есть?
5. Совпадает с исходным запросом?
6. Что опровергло бы вывод?
7. Где опирался на допущения, а не на факты?
8. Для данных/кода покажи 3–5 реальных примеров вывода.
```

## Формат отчёта
`Вердикт` → `Anti-Victory` → `Дрейф` → `Возражения` → `Верификация` (только расхождения) →
таблица `D/L/C/P` с доказательством → `Искажения` → `Тесты` → `Галлюцинации` → `Следующие правки`.
