# ship-check: проверка перед пушем в main

Пуш в `main` автоматически деплоит в прод, поэтому сначала всё зелёное.

1. Линт: `.venv/bin/ruff check .` — должно быть чисто (0 ошибок).
2. Тесты: `.venv/bin/python -m pytest -q` — все зелёные.
3. Если что-то красное — НЕ пушить; исправить и повторить шаги 1–2.
4. Пуш: `git push origin main` (спросит подтверждение — это деплой в ПРОД).
5. Проверить CI-пайплайн: дождаться, что стадия `test` зелёная и `deploy-prod` прошла.
6. Синхронизировать dev-стенд: `git pull origin main`.

## Когда НЕ использовать
- Схема БД менялась и миграция не создана — сначала `new-migration`.
- Правки ещё не готовы к деплою (это про последний шаг перед `git push`).
