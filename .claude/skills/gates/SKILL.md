# gates — приёмка перед завершением (концепт unlazy)

Проблема, которую решаем: агент уверенно рапортует «готово», а работа недоделана.
Лечение — записать проверяемые критерии ДО работы и заставить цикл упираться в них.

## Шаги
1. Сформулируй наблюдаемые критерии (один результат — один gate). Скопируй шаблон:
   `cp .claude/skills/gates/GATES.template.md docs/GATES.md` и заполни.
   Для каждого запускаемого гейта — команда `CHECK:` и ожидание `EXPECT:`. Если гейт нельзя
   проверить командой — сделай его ручным и явно пометь.
2. Включи приёмку (Stop-hook перехватит завершение хода):
   - `.claude/.verify-on-stop` — гонять `ruff check .` перед завершением;
   - `.claude/.verify-on-stop-full` — дополнительно полный `pytest -q` (медленнее, ~60 c).
   Маркеры не коммитятся (в `.gitignore`).
3. Работай. Когда все гейты закрыты и `ruff`/`pytest` зелёные — Stop-hook пропустит завершение.
4. Выключи приёмку по окончании: удали маркеры и `.claude/.stop-guard/`.
   Учти: progress guard сам снимет блокировку после 5 подряд неудачных завершений,
   чтобы не зацикливаться.

## Формулировка цели (если работаешь через `/goal`)
`/goal pytest зелёный и ruff чистый, либо стоп после 20 ходов`

## Границы
- Не создавай `GATES.md` для тривиальной правки.
- Не оставлять включённым Stop-hook между задачами (тормозит завершение хода).
- Область — наш репозиторий; критерии должны быть воспроизводимы (мы уже имеем pytest+ruff+CI).
