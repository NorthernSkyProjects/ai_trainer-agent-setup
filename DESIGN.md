# DESIGN.md — Kachlog

> Визуальная концепция и дизайн-система Kachlog. Основа — shadcn/ui `base-nova`,
> Tailwind v4, stone-палитра, Inter + Geist Mono. Teal — акцент прогресса и PR.
> Документ фиксирует палитру, типографику, сетку, компоненты, состояния, AI UX,
> motion и правила для новых экранов.
>
> **Референс интерфейса:** https://iitrainer.duckdns.org/next/plan
> **Дата:** 2026-11-14.
> **Scope:** `/next` UI (Next.js + shadcn/ui). Legacy Flask templates (`templates/`, `static/style.css`) keep the current visual language until migrated; do not mix the two systems.

---

## 1. Atmosphere

**Три прилагательных:** спокойный, плотный, точный.

Kachlog — не «мотивационный фитнес-лендинг», а **тихий тренажёрный инструмент**. Пользователь
приходит в зал, открывает приложение на телефоне и за 10 секунд понимает, что делать. Интерфейс
не кричит, не соревнуется с пользователем и не прячет данные за декором.

- **Плотность:** высокая на desktop (dense-контролы 28–40 px), комфортная на mobile (тач-цели ≥44 px).
- **Вариативность:** низкая. Одинаковые карточки, отступы, радиусы и состояния по всему продукту.
- **Моушн:** сдержанный, только для обратной связи и смены состояния.
- **Настроение:** «инструмент, которым пользуются каждую неделю», а не «приложение, которое
  продаёт подписку».

**Главный принцип:** один экран — одна задача. На `/plan` главный CTA — «Начать тренировку»;
на `/workout/today` — записать подход; на `/workout/result` — понять результат и вернуться к плану.

## 2. Colors

Палитра — **shadcn stone** с одним teal-акцентом для прогресса. Цвета задаются семантическими
токенами, не хардкодятся в компонентах.

### 2.1 Токены (light)

| Токен | Значение (OKLCH) | Роль | Доля |
|---|---|---|---|
| `--background` | `oklch(100% 0 0)` | фон приложения | 60% |
| `--card` | `oklch(100% 0 0)` | карточки, поверхности | входит в 60% |
| `--foreground` | `oklch(14.7% .004 49.25)` | основной текст | 30% |
| `--muted-foreground` | `oklch(55.3% .013 58.071)` | вторичный текст, подписи | входит в 30% |
| `--primary` | `oklch(21.6% .006 56.043)` | главный CTA, активные элементы | 10% |
| `--primary-foreground` | `oklch(98.5% .001 106.423)` | текст на primary | — |
| `--muted` | `oklch(97% .001 106.424)` | фоновые плашки, disabled | — |
| `--border` | `oklch(92.3% .003 48.717)` | границы, разделители | — |
| `--input` | `oklch(92.3% .003 48.717)` | границы полей | — |
| `--ring` | `oklch(70.9% .01 56.259)` | фокус | — |
| `--destructive` | `oklch(57.7% .245 27.325)` | ошибки, удаление | — |
| `--chart-1…5` | teal-шкала | прогресс, PR, графики | акцент |

### 2.2 Токены (dark)

| Токен | Значение (OKLCH) |
|---|---|
| `--background` | `oklch(14.7% .004 49.25)` |
| `--card` | `oklch(21.6% .006 56.043)` |
| `--foreground` | `oklch(98.5% .001 106.423)` |
| `--muted-foreground` | `oklch(70.9% .01 56.259)` |
| `--primary` | `oklch(92.3% .003 48.717)` |
| `--primary-foreground` | `oklch(21.6% .006 56.043)` |
| `--border` | `oklch(100% 0 0 / 10%)` |
| `--input` | `oklch(100% 0 0 / 15%)` |
| `--destructive` | `oklch(70.4% .191 22.216)` |

### 2.3 Акцент

- **Teal** — только прогресс, PR, графики, success-иконки. Источник — `--chart-2`
  (`oklch(70.4% .14 182.503)`), в тёмной теме тот же.
- **Amber** — предупреждения (`--color-amber-600` light, `--color-amber-400` dark). Только иконка;
  текст предупреждения — обычный `foreground`. Amber-600 на белом даёт ~3.2:1, для текста не использовать.
- **Destructive** — ошибки и удаление. Не использовать для «важных» кнопок.

### 2.4 Правило 60-30-10

- **60%** — background + card.
- **30%** — foreground + muted-foreground.
- **10%** — primary (CTA) + teal (прогресс).
- Один акцент на экран. Teal не конкурирует с primary: primary — действие, teal — результат.

### 2.5 Контраст

| Пара | Примерный контраст | Использование |
|---|---|---|
| `foreground` на `background` | ~17:1 | тело текста |
| `muted-foreground` на `background` | ~4.8:1 | подписи 12–14 px |
| `primary-foreground` на `primary` | ~16:1 | текст на CTA |
| teal `chart-2` на белом | ~2.3:1 | **только заливка/график, не текст** |
| `chart-3` на белом | ~3.7:1 | **не текст**; только графика/заливка |
| `chart-4` на белом | ~5.4:1 | текст-акцент, если нужен |
| `destructive` на белом | ~4.6:1 | ошибки |

Правило: если teal нужен как текст на светлом фоне — только `chart-4`/`chart-5`. `chart-2` и `chart-3` — графика и заливка, не текст.

### 2.6 Где менять

Только CSS-переменные темы (`:root`, `.dark`, `@theme inline`). В компонентах —
семантические классы `bg-background`, `text-foreground`, `border-border`, `bg-primary`,
`text-muted-foreground`, `bg-chart-2` (заливка) / `text-chart-4` (текст).
Никаких `#hex` в разметке и компонентах.

## 3. Typography

### 3.1 Гарнитуры

| Роль | Шрифт | Почему |
|---|---|---|
| Sans / body | **Inter Variable** | нейтральный, отличная кириллица, уже self-hosted |
| Heading | **Inter Variable** | единая система, без «дизайнерского» второго шрифта |
| Numbers | **Geist Mono Variable** | табличные цифры для весов, повторов, таймеров, процентов |

Fallback: `system-ui, sans-serif` / `ui-monospace, monospace`.
Шрифты подключены через `@fontsource-variable/*`, без CDN.

### 3.2 Шкала

| Токен | Размер | Line-height | Где |
|---|---|---|---|
| `text-[0.625rem]` | 10 px | 1 | бейджи «Сегодня» |
| `text-[0.6875rem]` | 11 px | 1.2 | мета, счётчики, подсказки |
| `text-xs` | 12 px | 1.33 | подписи, вторичный текст |
| `text-sm` | 14 px | 1.43 | тело карточек, кнопки |
| `text-base` | 16 px | 1.5 | базовый текст |
| `text-lg` | 18 px | 1.56 | заголовки карточек |
| `text-xl` | 20 px | 1.4 | заголовок страницы (mobile) |
| `text-2xl` | 24 px | 1.33 | заголовок страницы (desktop), hero |
| `text-3xl` | 30 px | 1.2 | hero на desktop |
| `text-4xl` | 36 px | 1.1 | большие цифры итогов |

Правила:
- Заголовки: `font-heading font-semibold tracking-tight`.
- Числа: `font-mono tabular-nums`. Вес, повторы, проценты, таймеры — всегда mono.
- Не использовать больше 3 размеров в одной карточке.
- Не использовать ALL CAPS для русского текста.
- Числа в тексте — с неразрывным пробелом: `85 кг`, `3 × 10`, `28%`.

### 3.3 Источники

- Google Fonts: Inter, Geist Mono (OFL).
- Typewolf / Fonts In Use — проверка пар и контекста.
- Текущий интерфейс продукта — фактическая шкала и веса.

## 4. Spacing & Grid

### 4.1 База

- Базовая единица — **4 px** (Tailwind `--spacing: .25rem`).
- Ритм — **8 px**: 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64.
- Радиус — **10 px** (`--radius: .625rem`); `md` = 8 px, `lg` = 10 px, `xl` = 14 px.
- Карточка: `rounded-lg bg-card ring-1 ring-foreground/10`.
- Тень — почти не используем; границы и ring важнее.

### 4.2 Контейнеры

| Экран | Ширина | Паддинги |
|---|---|---|
| План / Сегодня | `max-w-5xl` (64 rem) | `p-4 lg:p-6`, gap 16/20 |
| Итоги цикла | `max-w-3xl` (48 rem) | `p-4 lg:p-6`, gap 16/24 |
| Результат тренировки | `max-w-2xl` (42 rem) | `px-4 pt-6`, gap 16 |
| Онбординг | `max-w-md` / `max-w-2xl` | `px-4 py-10` |
| Sidebar | 16 rem, collapsible to icons | `SidebarProvider` |
| Mobile tab bar | full width, `max-w-lg` | safe-area bottom |

### 4.3 Сетки

- TodayCard: `md:grid-cols-[5fr_7fr]` — слева «что и когда», справа список упражнений.
- WeekStrip: horizontal scroll на mobile, `grid` по числу дней на desktop.
- Карточки итогов: `sm:grid-cols-2`, статы — `sm:grid-cols-4`.
- Не больше 2 колонок на mobile.

### 4.4 Отступы внутри компонентов

- Карточка: `p-4 md:p-6`.
- Строка списка: `px-3 py-2` / `px-4 py-3`.
- Кнопки: `h-11` mobile, `md:h-8` desktop (dense); главный CTA `h-12 md:h-10`.
- Иконка в кнопке: `size-4`; в hero — `size-6/7`.

## 5. Components

Все компоненты — shadcn/ui поверх Tailwind v4. Примитивы лежат в UI-слое,
рецепты — в дизайн-системе экрана. Не редактируем примитивы вручную без необходимости;
обёртки и варианты — через `cn()` и CVA.

### 5.1 Button

| Вариант | Стиль | Когда |
|---|---|---|
| `primary` | `bg-primary text-primary-foreground` | главный CTA |
| `outline` | `border-border bg-background` | вторичное действие |
| `secondary` | `bg-secondary` | альтернатива |
| `ghost` | без фона, hover `bg-muted` | иконки, «Отмена» |
| `destructive` | `bg-destructive/10 text-destructive` | удаление |

Размеры: `sm` (36/28), `md` (44/32), `lg` (48/40), `icon` (44/32).
Все кнопки: `focus-visible:ring-2 ring-ring/30`, `disabled:opacity-50`, `active:translate-y-px`.

Правила:
- Один primary на смысловой блок; на экране допускается максимум два (например, CTA тренировки и CTA повышения весов в отдельной карточке).
- Иконка + текст: иконка `size-4`, gap 6 px.
- Иконка без текста — только с `aria-label` и tooltip на desktop.
- Не делать кнопку `rounded-full`, если это не chip/бейдж.

### 5.2 Card

`rounded-lg bg-card text-card-foreground ring-1 ring-foreground/10`.
Внутри: заголовок `font-heading text-sm font-medium`, тело `text-xs/relaxed text-muted-foreground`.
Карточки не вкладывать глубже 2 уровней.

### 5.3 Badge / chip

- `outline` — нейтральный статус.
- `muted` — вторичный статус.
- `primary` — «Сегодня», активный фильтр.
- Высота 20 px, текст 11 px, `rounded-full`.
- Chip-кнопки (быстрые пожелания) — 36/28 px, `rounded-full`, активный = primary.

### 5.4 Input / textarea / select

- `rounded-md border border-input bg-transparent px-3`.
- Фокус: `border-ring ring-2 ring-ring/30`.
- Ошибка: `aria-invalid:border-destructive` + текст рядом, не только цвет.
- Подпись — над полем; placeholder — пример, не замена подписи.
- На mobile `min-h-11`, на desktop — компактнее.

### 5.5 Dialog / Sheet

- Desktop — `dialog` по центру, `rounded-lg`, `ring-1 ring-foreground/10`.
- Mobile — `sheet` снизу, `rounded-t-xl`, safe-area.
- Заголовок + описание + контент + футер с действиями.
- Pending можно отменить: «Отменить», Esc или клик по фону останавливают таймер и не показывают успех.
  В продукте `RegenerateDialog` сейчас блокирует закрытие — это расхождение, которое нужно привести
  к модели «отмена = явное действие пользователя».
- Destructive — подтверждение отдельным шагом.

### 5.6 Sidebar / MobileTabBar

- Sidebar: `variant="inset"`, collapsible to icons, cookie `sidebar_state`.
- Пункт: иконка 16 px + текст 14 px; активный — `bg-sidebar-accent`.
- Mobile: 4 таба + «Ещё», высота 64 px, safe-area, активный — `bg-accent`.
- Breadcrumbs — только desktop; mobile — заголовок страницы.

### 5.7 TodayCard

- Бейджи: «Сегодня», день недели, «Разгрузка».
- Заголовок тренировки — `text-2xl/3xl`, не больше 2 строк.
- Прогресс цикла: `9 из 32 · 28%`, полоса `bg-chart-2`.
- Главный CTA: «Начать тренировку» + иконка Play.
- Справа — список упражнений: номер, название, вес × повторы.
- Не добавлять сюда соцфичи и рекламу.

### 5.8 WeekStrip

- Заголовок «Неделя 3 из 8», справа «1 из 4 выполнено».
- День: короткий день недели, название, число упражнений.
- Статусы: done (галочка teal), current (ring primary), upcoming (dashed).
- Mobile: `w-[38%]`, snap-scroll; desktop: grid.

### 5.9 PlanAccordion

- Недели сворачиваются; текущая открыта.
- День: статус, название, день недели, число упражнений, chevron.
- Внутри дня — список упражнений с весом × повторами.
- Редактирование дня — отдельный dialog.
- Не показывать больше 2 уровней вложенности.

### 5.10 Progress / Skeleton / Toast

- Progress: высота 6 px, `rounded-full`, `bg-muted` + `bg-chart-2`.
- Skeleton: `animate-pulse bg-muted`, только для предсказуемой структуры.
- Toast: снизу по центру, `rounded-md`, 3–5 с, не единственный источник результата.

## 6. States

Каждый новый экран обязан иметь пять состояний. Это чек-лист для дизайна и ревью.

| Состояние | Обязательно | Пример |
|---|---|---|
| **Empty** | да | «Плана пока нет» + «Составить план» |
| **Loading** | да | skeleton или «Загружаем план…» |
| **Partial** | если есть асинхронность | `stale` разбор + базовый разбор |
| **Error** | да | причина + «Повторить» |
| **Success** | да | результат + следующий шаг |

Дополнительно:
- **Offline** — бейдж «Офлайн», форма не теряет ввод.
- **Slow** — после 60–90 с меняем текст, не крутим спиннер бесконечно.
- **Disabled** — `opacity-50`, объяснение рядом.
- **Permission/consent** — явный чекбокс, не предустановлен (здоровье, обработка данных).
- **Technical default** — например, «учесть историю»; может быть включён, если подписан и отключается.

Правила:
- Ошибка — простым языком, без кодов и трейсбеков.
- У ошибки всегда есть действие: retry, назад, открыть историю.
- Успех не должен быть только toast: результат остаётся на экране.
- Skeleton не должен «прыгать»: фиксируйте высоту.

## 7. AI UX

### 7.1 Принципы

1. **ИИ не скрывает данные.** Тренировка сохраняется даже при сбое разбора.
2. **ИИ объясняет.** Одна строка «почему» лучше абзаца.
3. **ИИ можно остановить.** Pending-состояние имеет «Отменить» или безопасный выход.
4. **ИИ можно повторить.** Retry только там, где это не ломает данные и не жжёт квоту.
5. **ИИ не притворяется человеком.** Подпись «Разбор тренера» — метафора, не врач.

### 7.2 Генерация плана

- До старта: «Что учтём» — цель, опыт, оборудование, ограничения; оценка 20–40 с.
- Во время: этапы (анализ профиля → подбор упражнений → проверка ограничений → сборка недель),
  прогресс, таймер.
- Ошибка: причина + «Повторить»; план не создаётся молча.
- Успех: сразу `/plan`, первый экран — «Сегодня».

### 7.3 Пересчёт плана

- Sheet/dialog: быстрые пожелания, комментарий, «Учесть историю тренировок».
- «Память тренера» раскрывается; видно, что учтено.
- Pending: «ИИ перестраивает план…», анимация, «Отменить».
- Ошибка: текст + возможность исправить комментарий.
- Успех: toast + обновлённый план без перезагрузки.

### 7.4 Разбор тренировки

| Статус | UI |
|---|---|
| `pending` | skeleton + «Обычно до минуты» |
| `ready` | резюме + по упражнениям + рекомендация |
| `stale` | «разбор задерживается» + базовый разбор + история |
| `failed` | причина + базовый разбор + retry |
| `skipped` | «сохранено без ИИ» + базовый разбор |

### 7.5 Стрим и оптимистичные обновления

- Текст разбора может появляться постепенно; не блокировать экран.
- Сохранение подхода — optimistic: сразу показываем, при ошибке — откат и сообщение.
- Квоту показываем до дорогого действия, если она ограничена.
- Не использовать «фальшивый прогресс»: проценты только по реальным этапам.

## 8. Motion

| Действие | Длительность | Easing |
|---|---|---|
| Hover/цвет | 150 ms | ease-out |
| Открытие accordion | 200 ms | ease-out |
| Sheet/dialog | 220 ms | ease-out |
| Toast | 200 ms | ease-out |
| Skeleton pulse | 1.8–2 s | linear |
| Ping вокруг AI-иконки | 2 s | ease-out |
| Появление карточки | 300 ms | ease-out, задержка 60 ms на элемент |

Правила:
- Анимируем только `opacity`, `transform`, `max-height`, `width` прогресса.
- Не анимировать layout-свойства без необходимости.
- `prefers-reduced-motion: reduce` отключает fade/slide/ping.
- Нет параллакса, autoplay-видео, «прыгающих» градиентов.

## 10. Don'ts

### Визуал

- ❌ Градиенты, «стекло», неоновые свечения, aurora-фоны.
- ❌ Больше одного акцента на экран; teal и primary не соревнуются.
- ❌ Эмодзи в карточках и заголовках.
- ❌ Смешивать шрифты: только Inter + Geist Mono.
- ❌ Круглые кнопки «на всё»; `rounded-full` — только бейджи/chips.
- ❌ Тени вместо границ; «парящие» карточки без ring.
- ❌ Хардкод hex/oklch в компонентах.
- ❌ Копировать логотипы, тексты, фото и бренд конкурентов.

### UX

- ❌ Два равноправных primary CTA в одном смысловом блоке (на экране — максимум два в разных блоках).
- ❌ Скрывать ошибку ИИ или подменять её молчаливым fallback.
- ❌ Заставлять пользователя ждать на экране генерации без возможности уйти.
- ❌ Требовать лишние поля в логе подхода.
- ❌ Соцлента, лидерборды, публичные профили в текущем scope.
- ❌ «Умные» рекомендации без объяснения.
- ❌ Фальшивая точность: «вы восстановлены на 87%», если нет данных.
- ❌ Тёмные паттерны: предустановленное согласие на здоровье/обработку данных, скрытая отмена, fake urgency.
  Технические настройки по умолчанию (например, «учесть историю») допустимы, если подписаны и отключаются.

### Контент

- ❌ Медицинские советы и диагнозы.
- ❌ Обещания результата («+5 кг за месяц»).
- ❌ Английские подписи в русском UI.
- ❌ Технические коды ошибок вместо человеческого текста.

## Приложение A. Ограничения концепта

- Белые галочки «выполнено» на teal `chart-2` не используем: контраст ~2.3:1 ниже 3:1
  для нефоновой графики. В demo — тёмный ink на teal.
- Teal и amber — не текстовые цвета на светлом фоне (см. §2.5). Для текста — `chart-4`/`chart-5`
  или обычный `foreground`.
- Палитра проверена в light/dark; скриншоты — desktop 1440×900 и mobile 390×844.

## Приложение B. shadcn-правила для новых экранов

1. Сначала проверь, есть ли подходящий примитив в UI-слое; не создавай новый без причины.
2. Используй семантические токены (`bg-card`, `text-muted-foreground`, `border-border`).
3. Варианты — через CVA/`cn()`, не через inline-style.
4. Новый экран собирается из `AppShell` + `max-w-*` + карточек; не изобретай свой layout.
5. Числа — `font-mono tabular-nums`.
6. Mobile — `min-h-11` для интерактивных элементов; desktop — dense.
7. Фокус обязателен: `focus-visible:ring-2 ring-ring/30`.
8. Иконки — Lucide, `aria-hidden` для декоративных, `aria-label` для кнопок.
9. Тёмная тема — проверяй каждый новый токен в `.dark`.
10. Скриншоты — desktop 1440×900 и mobile 390×844, light + dark.
11. Тема: класс `.dark` или атрибут `[data-theme="dark"]`; demo поддерживает оба варианта.
